# 无损视频剪辑工具 更新历史

## v13.4 (2026-09-27) 「播放选区」语义修正

### 修复
- **「播放选区」现在播放框选的那一段**:播放起点固定取**选区起点**,不再受播放头(红针)位置影响
  - 旧逻辑写作 `start = max(播放头, 选区起点)`:只要在时间轴上点过一下(移动播放头做单帧预览),
    再点「播放选区」就会从那个插针位置开始播,而不是框选范围的起点 —— 与按钮语义不符(用户反馈)
  - 现在:无论插针落在**选区内 / 选区之前 / 选区之后**,一律从**选区起点播到选区终点**;
    播放过程也不再移动播放头(插针位置保持不变)
  - `-t` 时长同样改为整段选区长度(end - start),此前会随起点漂移而变短
- 空选区(起点 = 终点)的提示文案改为「当前选区为空(起点 = 终点)…请在时间轴上拖出端点、
  框选一段区间后重试」。旧文案「播放头已到选区末尾,请把播放头往左拖」建立在旧语义上,已失效。
- 运行日志由「播放预览: … (从播放头起, …)」改为「播放选区: … (选区范围, …)」

### 说明
- 「⏮ 起点 = 播放头」「终点 = 播放头 ⏭」按钮、以及拖动播放头实时预览单帧,均**保持不变**。
  播放头从此只代表"当前查看的这一帧",不再参与播放起点计算。

## v13.3 (2026-09-27) 播放启动反馈 + 取消时间轴双击

### 新功能
- 「播放选区」启动反馈:点击后**立即**在底部显示"正在启动播放器…"(不确定型进度条)并在状态栏提示,
  之后每 0.12 秒检测 ffplay 的「无损预览」窗口,窗口一出现即自动收起并转为"正在播放预览…"
  - 实测:720p 素材窗口约 0.6 秒出现;4K / 高码率素材的 seek + 首帧解码可达数秒,这段时间此前界面完全静止
  - 超过 1.5 秒会在进度条与状态栏显示已等待秒数;超过 20 秒仍无窗口则弹窗说明可能原因并建议开启硬件加速
  - 补上两处静默分支的明确提示:① 未打开视频 ② 播放头已在选区末尾(此前是静默 return,观感就是"点了没反应")
- 进度条占用改为**优先级制**:play(0) < import(1) < export(2)。
  播放的启动提示不会抢占导入 / 导出的进度显示,也不会误关它人的进度条。

### 变更
- **取消「双击时间轴 → 精确设置」**:双击时间轴现在等价于两次单击(纯跳转定位)。
  精确设置仍可从顶栏「精确设置」按钮打开;预览区双击(还原 100% 缩放)与片段列表双击(定位片段)保持不变。

### 说明
- 窗口检测用 ctypes 调 user32.FindWindowW(按窗口标题),**零第三方依赖**(项目仍只用标准库 + tkinter)。
- 检测不可用(非 Windows / 被拦截)时直接放弃反馈,不显示假进度条。

## v13.2 (2026-09-27) 进度反馈 + 硬件加速

### 新功能
- 导入进度条:打开视频时的 ffprobe 解析阶段显示不确定型进度条(此前只有一行文字提示)
- 预览解码指示:抽帧超过约 250ms 时,预览区左上角浮出"◌ 解码中…"动画,拖动播放头不再"无感"
- 硬件加速解码开关:控制栏新增「硬件加速解码」复选框,默认关闭,状态保存到 config.json
  - 开启后预览抽帧 / ffplay 播放 / GIF 重编码走 GPU 解码(-hwaccel auto),4K、高码率、HEVC/AV1 素材收益明显
  - 裁剪/合并是无损 stream copy,不参与解码,故画质零损失、不受开关影响

### 优化
- 导出进度条左侧显示具体任务名与百分比(如"裁剪导出中… 42.5%"),取消按钮文案统一为「✕ 取消」
- 进度条升级为通用任务条:导入/导出共用,带占用者互斥(导出期间不会被导入/预览抢占或误关)
- 进度条改为自绘琥珀色样式:系统默认(vista)填充是绿色,在 OBS 深色蓝调界面里很突兀;
  改为 default 主题 + 自定义颜色,填充取琥珀色(语义配色"主操作/进度"),深底高对比,色弱也更清晰

### 说明
- 硬件加速默认关闭有实测依据:720p 小文件上 GPU 初始化开销反而更大(663ms vs 254ms),
  只有 4K / 高码率 / 重解码格式才划算,因此做成按需开启的开关而非默认打开。

## v12 (2026-08-17)

### 新功能
- 片段列表多选：Shift+点击范围多选、Ctrl+点击逐个多选；多选后可批量删除、块移动（保持相对顺序）；右键菜单自动显示"删除选中 (N)"
- 导出参数记忆：GIF/MP3 质量档位选择后自动保存到 config.json，下次导出默认选中上次的档位

### 修复
- **速度下拉框卡死修复**：v11 的自定义 Toplevel + overrideredirect + grab_set + wait_window 方案在 Windows 上导致 grab 死锁、整个软件卡死无法关闭；v12 改用原生 Menu.tk_popup()，无 grab、无 wait_window、自动关闭
- **对话框 z-order 安全**：所有 Toplevel 对话框（质量选择/完成提示/精确设置/ffmpeg解压/下载/重命名）增加 lift() + focus_force()，确保弹出时在最前，防止被主窗口遮挡导致"假卡死"
- **导出按钮防重复点击**：所有导出函数（裁剪/合并/GIF/MP3/批量）增加 busy 守卫，导出进行中再次点击直接返回，防止并发 ffmpeg
- **质量选择弹窗超时保底**：5 分钟未操作自动关闭并释放 grab，防止 grab 永久占用导致卡死
- **关闭时竞态兜底**：_speed_popup 在应用销毁过程中被触发时静默忽略，不再写入 crash.log

## v7 (2026-08-17)

### 修复（3 个确认 bug）
- 「精确到帧(慢,不重编码)」勾选框现在真正生效：勾选时 -ss 移到 -i 之后做慢 seek（帧级精确），不勾选时 -ss 在 -i 前快 seek（秒级定位）。此前两个分支命令完全相同，勾选框无效
- 播放选区起点错误：播放头在选区起点之前时，实际播放 0~终点 而非选区内内容。现在起点取「播放头」与「选区起点」的较大者并限制不超过终点
- 预览抽帧临时文件同名冲突：快速拖动时间轴时并发抽帧线程写同一 png 可能错帧。已加唯一后缀

### 体验优化
- 打开视频不再卡界面：ffprobe 解析移入后台线程，大视频秒开，界面即时响应
- 导出文件名默认跟随源文件扩展名（mkv/avi 等源不再强转 mp4 导致失败）
- 导出进行中直接关闭窗口会中止后台 ffmpeg 进程，不再残留占用输出文件
- 片段列表长文件名截断显示（超过 58 字符自动省略），不再撑破面板
- 窗口位置恢复增加屏幕边界校验：上次窗口在已拔掉的外接屏上时，自动回到默认位置

### 体积优化
- 内置 ffmpeg-bundle.zip 剔除 40 个无用文件（32 个 HTML 文档 + 3 个 CSS + 5 个编码 preset），zip 从 162.7MB 降到 160.5MB
- 清理项目残留构建目录约 3.7GB（build_dbg/build_old/dist_old/dist_v3/ffmpeg_backup 等）
- 说明：尝试更换 essentials 精简版 ffmpeg（可再省约 40MB）因网络下载过慢放弃，后续网络条件允许时可再实施
